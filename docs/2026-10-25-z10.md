# Z10 — подключение WhatsApp по коду; группы владельца по темам

## 1. Подключение по коду (запасной путь, QR без изменений)
- **Где кнопка.** Под QR — ссылка «Подключаюсь с этого телефона». На экранах ≤600 px вместо неё заметная вторичная кнопка в начале блока подключения: с экрана самого телефона QR не отсканировать.
- **Как выглядит.** Номер бизнеса с кодом страны: тот же ввод и нормализация, что в Z9. Дальше «Получить код» → код крупно и три строки «куда ввести» → «Получить новый код» / «Вернуться к QR». Тексты ru/he/en.
- **Бэкенд:** `POST /api/admin/waha/pairing-code` → WAHA `POST /api/{session}/auth/request-code {"phoneNumber":"<цифры>"}`. Имя устройства не задаётся.
  - Код можно получить, только пока сессия ждёт сканирования (как QR).
  - Ошибки WAHA уходят в кабинет кодами (`pairingFailed`, `pairingUnavailable`, `pairingPhoneInvalid`) и показываются простыми словами, технический текст не виден.
- **Не проверено на реальных телефонах.** Подключение на iPhone и Android требует живой сессии и тестового номера — это не сделано. Проверено мок-сервером: экран, запрос, код, повтор, ошибки. Скриншоты лежат в `docs/2026-10-25-z10/`.

## 2. Группы владельца
- **Темы и названия.** Реестр `owner_channels`, темы в конфиге `src/config/owner-channels.ts`: `needs_answer`, `reports`.
  - Названия и описания групп — шаблоны `owner.channel_*` (ru/he/en). `{имя}` — имя ассистента.
  - Язык названий — `owner_language`; если не задан, английский.
  - При смене языка владельца или имени ассистента группы переименовываются (`PUT subject`).
- **Что куда идёт.**
  - «Нужен ответ»: вопросы клиентов, заявки, напоминания, интервью, «пропущенное напоминание».
  - «Отчёты»: сводки и уведомления о лимитах.
  - Код подтверждения номера по-прежнему уходит на личный номер.
- **Ленивое создание.** Группа создаётся при первом сообщении по теме.
  - Раз в `owner_channel_check_minutes` (операторская настройка, по умолчанию 60) проверяется, что группа жива.
  - Пропала или ассистента удалили → создаётся новая, и в ней одна строка «Прежняя группа недоступна — теперь пишу сюда».
  - Если проверка просто не удалась (сеть, перезапуск WAHA), группа не пересоздаётся.
- **Разные номера.** Участник группы — личный номер владельца. В старый личный чат один раз уходит строка «Теперь пишу вам в группах „… · Нужен ответ“ и „… · Отчёты“».
- **Один номер на бизнес и личное.** Владелец указывает в «Настройках» сам номер бизнеса. Он сохраняется как номер владельца без кода: себе код не отправляется, кабинет пишет «Это номер бизнеса — буду писать вам в группах WhatsApp».
  - Группа сначала создаётся без участников.
  - Если WhatsApp так не даёт — с временным участником `system_config.group_bootstrap_number`, которого сразу удаляем.
  - Какой путь сработал, пишется в `system_logs` (`owner_channel_created.details.path`).
  - В чат с самим собой ничего не уходит — это проверено тестом.
- **Чтение ответов владельца.**
  - Сообщения в группах из `owner_channels` обрабатываются как сообщения владельца: цитата → ответ клиенту, команды, ответы на интервью. Ответы ассистента уходят в ту же группу.
  - При одном номере это исходящие сообщения аккаунта. Свои отправки ассистента отсекаются по `source=api`, по известным id отправленных и по совпадению с отправкой из очереди.
  - Чужие группы и другие участники группы владельцем не считаются.
- **Смена номера владельца (ревью).** В строке канала хранится, для какого владельца сделана группа (`owner_chat`). После подтверждения нового номера старая группа помечается `retired`, прежний номер удаляется из неё, а для нового владельца создаётся новая группа. Неподтверждённый новый номер ничего не меняет: всё идёт старому, как в Z9.
- **Гонка (ревью).** Создание и пересоздание группы идут по одному на пару «тенант + тема». Блокировка внутри процесса — `leya-api` работает в одном экземпляре, cluster mode запрещён. Уникальный индекс остаётся последней защитой.
- **Allowlist (тестовые окружения):** группы владельца разрешены, только если разрешён номер самого владельца.

## Тесты
- **Бэкенд, PGlite:**
  - ленивое создание (только нужная тема) и одна строка в личный чат;
  - один номер: путь без участников;
  - временный участник → удалён; без него группа не создаётся и себе ничего не уходит;
  - пересоздание потерянной группы;
  - сообщения владельца в группе распознаются, свои отправки ассистента — нет;
  - ответ владельца цитатой доходит клиенту;
  - переименование при смене языка и имени;
  - номер бизнеса как номер владельца: без кода.
- **Бэкенд, контракт WAHA:** пути и тела запросов кода и групп.
- **Кабинет:** маршрут кода (E.164, коды ошибок, роль), панель «этот телефон».
- **Прогоны:** бэкенд — build, typecheck, 187 быстрых и 381 интеграционный; кабинет — build, lint, 266 тестов.
- Поведение модели не затронуто (промпты и инструкции не менялись) — eval не нужен.
- **Внимание:** при отладке несколько раз запускал отдельные интеграционные тесты напрямую через `node --test`, в обход `npm run`. Ключи моделей из `.env` при этом не обнуляются, так что было несколько настоящих вызовов модели. В штатных прогонах (`npm test`, `npm run test:integration`) ключи обнулены.

## Не сделано / нужно от Юрия
- Ручная проверка на тестовом номере (раздельный и смешанный режим) и скриншоты групп не сделаны: нужен живой WhatsApp и телефоны.
- `system_config.group_bootstrap_number` — значение не задано: номера Юрия в репозитории нет, его ставит оператор.
- `system_config.owner_group_picture_url` — логотипа Леи как файла в репозиториях нет. Пока URL пуст, картинка группы не ставится.
- Миграция **067_owner_channels** не применена — применяет Юрий до деплоя бэкенда. 064–066 — как раньше.
